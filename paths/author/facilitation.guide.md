# Facilitation guide

## Teaching stance

Programming is learned by making predictions, running code, observing the
result, and revising. Explanation matters, but it should lead quickly back to
student action.

Manual typing is purposeful practice in the foundations unit. The physical and
mental loop of seeing, typing, running, and correcting code helps learners form
reliable program patterns, much as scales build musical fluency or repeated
movement builds physical coordination. Keep the repetitions short and tied to
a named capability; avoid turning them into long transcription exercises.

Use the course's recurring sequence:

> Understand the problem → plan a small step → write code → run it → inspect
> the result → revise → explain what changed.

## When a learner is stuck

Ask for three concrete things before offering a solution:

1. What did you expect to happen?
2. What actually happened, including the exact error?
3. What is the smallest relevant section of code?

Then choose the least invasive support that can restart the learner:

- restate the goal in plain language;
- trace one example by hand;
- reduce the task to a smaller input;
- point to a relevant worked example;
- provide a staged hint;
- pair on diagnosis while leaving the next line to the learner.

## Mixed prior experience

Every learner completes the same core evidence. Faster learners should deepen
the work through edge cases, clearer decomposition, tests, or a stretch goal;
they should not race ahead by replacing practice with a larger unexplained
project.

For learners new to files, provide a Thonny recovery route at the point of
need. Introduce terminals and Git later, when the project structure makes their
purpose visible. Let learners demonstrate programming capability separately
from a temporary environment failure.

## Feedback

Prefer one or two actionable priorities over exhaustive correction. Name:

- what the program currently does;
- the evidence supporting the judgment;
- the next change to make;
- how the student can tell that change worked.

## Accessibility

- Do not encode meaning using color alone.
- Make code and diagrams readable without presentation animation.
- Provide text alternatives for meaningful media.
- Make instructions usable with a keyboard and on a narrow display.
- Offer equivalent local and browser environments when feasible.
- Follow approved accommodation plans and institutional policy.

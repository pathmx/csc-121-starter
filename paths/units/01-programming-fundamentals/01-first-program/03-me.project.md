# Application: `me.py`

Build a static text profile card. The project is small enough to complete in
phases and rich enough to show why variables and expressions matter.

## Required behavior

Running `me.py` with **F5** in Thonny should print a card containing:

- a name or chosen display name;
- a short, non-sensitive bio;
- one interest or goal;
- a top and bottom border.

Do not put a private address, phone number, password, or other sensitive data
in a course file.

## Phase 1: Literal output

Use one `print()` statement for each line. Make the output readable before
making it flexible.

Example with fictional data:

```text
+--------------------------------+
| Ada Rivers
| Learning to make useful tools
| Goal: build a tiny game
+--------------------------------+
```

Run it and save the working card before continuing.

## Phase 2: Variables

Move the display name, bio, and goal into clearly named variables at the top of
the file. The output should remain the same.

Run it and save the refactor.

## Phase 3: Generated border

Create one `border_width` variable and generate both borders from it using
string multiplication and concatenation.

Run it and save the change.

## Stretch: Trait bars

Store three values from 0–10 and display a ten-character bar for each:

```text
Curiosity:     ████████░░ 80%
Persistence:   █████████░ 90%
Collaboration: ███████░░░ 70%
```

This is optional. A clear, correct Phase 3 submission is complete.

## Evidence checklist

- [ ] `me.py` runs with **F5** in Thonny.
- [ ] At least four meaningfully named variables are used.
- [ ] One variable controls both borders.
- [ ] Output is readable and contains no sensitive information.
- [ ] The file is saved with the exact name `me.py`.
- [ ] The intended file is uploaded through the stated submission channel.
- [ ] You can explain string multiplication and each variable.

# How this course works

CSC-121 is a course about solving problems with code. You will spend more time
writing, running, reading, and revising programs than listening to explanations
about them.

PathMX is the course website: it gives you the guided sequence and references.
During the foundations unit, you will write and run Python in Thonny. Later,
project work will introduce VS Code, Codespaces, Git, and GitHub one step at a
time.

## The weekly rhythm

Most weeks have four connected parts:

1. **Lesson:** see and discuss a new capability.
2. **Lab:** try it with guidance and immediate help.
3. **Application:** apply it independently to a related problem.
4. **Feedback:** explain your work and decide what to improve next.

The lab is preparation for the project. Start early enough to ask questions
before the project deadline.

---

## Your working loop

When you solve a programming problem:

1. describe the desired behavior in your own words;
2. choose one small testable step;
3. write the smallest code that can try that step;
4. run it and compare the result with your prediction;
5. fix or extend it;
6. save a working checkpoint; and
7. explain what the program does now.

You are not expected to see the complete solution before you begin. Productive
programming replaces a vague large problem with a sequence of observable small
ones.

---

Manual typing is part of the practice. The coordination between reading code,
typing it, predicting it, and observing it helps the syntax and program shapes
become familiar—much like practicing scales or a movement repeatedly. Do not
replace that practice with pasted or generated code.

---

## What counts as submitted

In the foundations unit, your work is submitted when:

- the required `.py` file is saved with the exact filename;
- it runs in Thonny in the documented way;
- required files have the correct names;
- it is uploaded through the course's stated submission channel; and
- you can explain the code you submitted.

Applied and final projects add Git commits and a GitHub repository. Your
instructor will teach and test that workflow before it becomes a requirement.
Use the [save and submit guide](../resources/commit-and-submit.guide.md) when
you are unsure which workflow applies.

---

## Getting help

Bring these three things:

1. what you expected;
2. what actually happened, including the full error message;
3. the smallest code section that seems related.

See [debugging without guessing](../resources/debugging.guide.md) for the full
recovery loop.
